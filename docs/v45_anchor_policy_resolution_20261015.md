# v45 月度锚点约束冲突修复

日期：2026-10-15。用户在首次冲突诊断后要求“想办法解决”。本次采用保留换手硬上限的因果有效锚点政策，没有提高8%额度。

## 为什么能解决

原系统要求目标立即跟随变化较大的底仓，又限制主动偏离和总目标变化。2019-01中波的三个条件同时成立时无解。

修复后同时保存原始锚点和有效锚点。仅当原锚点与当前限制冲突时，选择离原始锚点最近、且存在合法目标组合的有效锚点。使用的只有当期锚点、上一期合法目标和已声明边界，不读取未来收益。

这是明确的策略行为变化，不是声称原约束本来就可行。主动偏离上限现在相对于有效锚点检查；相对于原始锚点的偏差单独保留，不将其隐藏。

## 精确问题

第一步求有效锚点 a 和可行目标见证 z：

```text
minimize ||a - raw_anchor||_2^2
subject to:
    sum(a) = sum(z) = 1
    lower <= a,z <= upper
    ||z - previous_target||_1 <= unchanged_total_change_limit
    ||z - a||_1 <= unchanged_active_limit
```

z只证明存在可行目标，不是最终收益优化结果。第二步以a为有效底仓，使用严格skfolio优化真实目标，再独立检验预算、上下限、总L1目标变化和主动偏离。

原锚点已经可行时原样返回，不平滑全部日期。资格和盒约束本身无解时仍报错，不能靠改变锚点免除资格限制。

24项求解器边界测试全部通过。三产品各90个月度核心优化时点顺序扫描通过，热身段仍单独标为not_enough_history，没有伪称完成优化。

第二次冲突比旧版的8.3145%更大，是因为本次上一期目标已经沿修复后的顺序路径变化。不能直接用旧权重替换修复后的上一期目标。

本次“目标变化”不是实际成交换手；PPO、成交会计、报价限制、日频guardrails和资产层全路径仍需独立检验。上述扫描没有证明投资收益提高。
