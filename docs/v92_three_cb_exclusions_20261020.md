# V92：按用户要求排除三只转债

## 已执行的范围

2026-10-20用户明确要求，不再考虑蓝盾、搜特、广汇三只转债。本版本从全历史研究可投券池排除：

| 证券 | 原交易所代码 |
| --- | --- |
| 蓝盾 | 123015.SZ |
| 搜特 | 128100.SZ |
| 广汇 | 110072.SH |

38个资产标识、12个转债风格篮子均保留，利率、信用、权益、另类部分不修改。没有将转债风格资产本身删除，也没有删除原始数据、旧库存或旧版回测记录。

配置为`config/cb_research_exclusions_v92.json`，实现为`src/v92_cb_research_universe.py`。排除发生在可投资格过滤及篮子构建之前；然后重新计算其他券的权重，从初始资金重新走交易账，不在旧账上抹去证券或凭空释放现金。

## 历史口径须明确

这是用户在2026-10-20指定的全历史研究筛选。原数据始于2018-01-02，在当时并不能从后来结果预知应剔除这三只。因此本版明确记录`retrospective_universe_selection=True`、`strict_no_lookahead_claim_allowed=False`。

不能将本版称为严格无前视的样本外检验，也不能因它减少缺口或改善任何历史结果就认定策略有效。执行仍使用上一交易日信号、原历史报价、原费用和已核实事件；这些时点保护不能消除全历史选券的事后筛选属性。

净减少1,839个缺口，但这不是对原回测净值的修复，而是重新选券后的另一条历史路径。重新分配权重会改变其他券的持仓，不能只从旧缺口总数中减掉这三只。

未决应收款因实际持仓路径改变，合计变为7,078.06元；不代表旧天马、希望的证据冲突被解决。

## 检查通过了什么

- 其他1,009只券的原可投资格逐格不变；三只被排除券的资格全为False。
- 三券没有目标权重、成交或期末库存；原文件未修改。
- 原38资产、12篮子结构数量检查通过。
- 成交信号全部对应上一原行情交易日；实际买卖金额双向5bp成本逐日核对通过。
- 无负库存、无现金透支；认证总回报净值仍为空。
- 131个绑定源哈希检查通过；V9相关25项测试通过，其中新增排除规则5项。

原始行情文件有1,075列，原V51研究集合为1,012列。首次运行的坐标检查拒绝直接把两个集合混用；随后按原V51披露余额矩阵对齐至原研究集合，其他63只没有因此新增纳入或本轮删除。

## 如何使用与保留边界

本轮新入口：

```powershell
python -X utf8 scripts/replay_v92_excluded_cb_universe.py
python -X utf8 scripts/audit_v92_excluded_cb_universe.py
```

主要输入输出：

| `config/cb_research_exclusions_v92.json` | 三券名单及事后筛选披露 |

| `output/reports/cb_cashflows_v92/gap_key_comparison_NOT_returns.csv` | 旧缺口消失和新缺口出现的逐条对照 |
| `output/reports/cb_cashflows_v92/status.json` | 重放进度、口径和源哈希 |
| `output/reports/cb_cashflows_v92/audit.json` | 独立审计 |

旧`run_v1_full_pipeline.py`和既有模型输入未被悄悄覆盖；运行旧入口不会自动变成V92。本轮只完成三券排除后的篮子重建与记账核对，没有重训iTransformer/PPO，也没有重跑完整三产品组合。后续重建训练标签时必须显式绑定本版来源、重新核查剩余现金流，不能沿用旧模型预测后称其已适配新券池。

普通付息、其他退出事件及完整38资产总回报认证仍需继续。本次剔除三只不自动消除这些问题，未发布新的收益或夏普结论。
