## 一、先解决收益口径，而非直接再训

本地已有4,385条年度票息合同。合同能说明利率和计息期，不能自动证明登记日、除息日、付款日和实际付款。只用价格涨跌会漏息，按周年日强行加息也可能记错时点。

本轮用V92排除三券后的实际模拟成交重建候选持仓，再用合同周年信息生成调查线索：

- 780只券涉及2,083个候选付息事件，展开为2,728个篮子×事件。
- 与已核实终止事件重叠或已经注销的候选不直接重复计息。
- 这只是按潜在持仓金额排序的查证队列，不是已确认的现金流数据库。
- 周年日及上一交易日都是查询提示，登记日必须重新核对原公告。
- 三只已排除转债没有重新纳入。

候选按参考金额排序只决定查证先后，不作为历史信号、持仓筛选或收益修正。当前发行人名称也仅用于查公告。

## 三、实际重放与登记权利

使用V92原执行器和独立的付息事件适配器，从初始资金重新跑2018-01-02至2026-10-14的12个转债篮子，完成2,127个执行日。用时约70秒。

原执行器源文件未修改；仅在独立进程中明确指定V93输出目录和增加两笔方案的记账类。额外原文与适配器哈希在执行前登记、执行后复核，新输出登记这些依赖。V92输出没有覆盖。

| 项目 | 实际结果 |
| --- | ---: |
| 电气事件非零登记篮子 | 8 |
| 电气税前方案应收权利 | 7,191.51元 |
| 浦发事件非零登记篮子 | 1 |
| 浦发税前方案应收权利 | 4,098.33元 |
| 两笔合计方案应收权利 | 11,289.84元 |
| 两笔已确认付息现金 | 0元，表示本版未放行确认 |

数量来自本轮重新执行后的登记日持仓，不是把上一版的查证参考金额直接抄成权利。加入应收款也可能影响后续资产规模和调仓，因此浦发的新登记金额与原查证提示略有不同。

“已确认现金为0”仅是本研究账的证据状态，不能解读为现实中发行人未付款。两笔`confirmed_at`均为空；登记后在除息日形成方案应收，不作为可直接支用的现金，也没有把债券持仓注销。金额税前，投资者税务未建模。

合计跨12个独立假设资金篮子，不能当作某一个产品的新增收益。应收款进入临时记账资产不代表已认证总回报或无信用风险。

## 四、检查结果

- 逐笔从本轮实际成交重算登记数量，再核对每张金额、应收总额及除息日转入时间，两笔通过。
- 事件转换中没有这两笔的确认现金支付记录。
- 首笔除息日前的3,180个篮子日记账行与V92逐格一致。这仅是该历史前缀检查，不是全策略未来数据认证。
- 原三券仍无成交和库存；38资产及12篮子结构保留。
- 原T+1执行、实际成交金额双向5bp费用、非负现金与非负库存检查通过。
- V93绑定140个执行输入源的哈希；新增5项事件测试通过，V9相关合计30项通过。
- 测试出现Pandas对空表拼接类型推断的FutureWarning，未影响本次结果；没有为了消除警告修改已经绑定的执行源。

缺估值仍为5,642个篮子×证券×日，期末仍涉及中装、正邦、全筑、普利。补票息不能解决这些退出和估值问题。认证总回报净值继续为空，训练和正式晋升仍未放行。
