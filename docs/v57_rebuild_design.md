# V57 预测、收益账本与PPO接口重构

## 目标与实施范围

本轮是用户在V53/V55/V56结束后明确授权的新研究阶段，不恢复原夜间自动任务，也不覆盖旧版。顺序为可预测性体检、收益证据核验、多任务预测训练、原门控复核、PPO执行授权检查。正式执行未获认证时停止，而不是借旧收益跑PPO。

## 一、先回答有没有可预测信号

`audit_v57_rebuild.py`逐年度、资产、5/20/60期限拆分实际已有预测，给出资产自身的时间维度RankIC、F0时间IC、神经增量对真实残差的IC，以及增量尺度。计算只用于诊断，不进入输入或调参。高度重叠标签按日期处理，额外报告近似不重叠块数，不把38资产乘交易日当独立样本。

2024–2026此前已反复观察，诊断不是新鲜样本外。应在新数据到来前冻结后续策略；不能靠反复挑测试期最好版本证明有效。

## 二、多任务iTransformer

保留38个资产、五个风险袖套、120个交易日窗口、21个局部特征、11个九宫格/连续轴特征，以及原年度T/V/G/test、126日验证、126日门控、60日隔离。严格输入中的九宫格目前是价格证据重构的几何状态，不是用户原始宏观状态卡完整规则；不以名称相同冒称完全还原。

Phase A复用V55各年度、各随机种子已经真实自监督训练的2层4头/d_model40 iTransformer。每个编码器只在该折历史T上训练，V用于选择；新模型不从全样本编码器抽特征。T-only clipping与原编码器一致，编码器在本阶段冻结并缓存表示，避免每轮重复重构和无证据解冻增加方差。新增非线性共享资产头与袖套头，训练的是新任务，不把原线性F1假称为新模型。

每个实体输出未来5/20/60日的：

- 相对机会目标的10%、50%、90%条件分位数；通过正间距构造避免交叉。
- 单独的条件均值头，用平方误差训练。均值不等于中位数，不用三个分位点臆造均值。
- 自身未来路径最大回撤，用信号日已知波动尺度归一化；任一未来日收益缺失则该标签无效，不补0。

目标沿用V55因果风险尺度与已成熟历史常态。未来回撤只作训练标签，不作为任何当期输入。模型输入不含未来收益、回撤、label mask或测试标签。

损失在日期和袖套内均衡，而不是让信用债低波动样本数量支配：0.15/0.50/0.35期限权重；pinball + 0.20*总均值观点pairwise + 0.25*下行风险Huber + 0.10*均值MSE；资产与袖套任务各0.5。固定预设，不根据2024–2026收益搜索。1000epoch上限、至少50轮、每5轮验证、耐心40轮；早停按V联合损失，不强迫跑满1000轮。区间覆盖率另报，不把名义80%区间宽度称为80%正确率。

三种子17/29/47，2022–2026五年度。训练新的头而非重新训练冻结编码器，必须如实披露。Phase B最后一层微调不是自动追加：只有新任务验证证据支持才另行预注册，不能为了声称“重训”直接解冻全部模型。

## 三、接入EP与风险层的单位

条件均值、各分位数分别按`(prediction + offset(t,h))*scale(t,h)`还原为未年化相对收益。条件均值供后续mean views研究，区间宽度作不确定性，不当作协方差、绝对收益或PPO奖励。下行风险乘scale还原成自身价格路径回撤，不能加offset，也不是已认证总回报风险。

预测parquet分别保存mean、median、lower、upper、downside、units与`deployment_allowed=False`。不修改原EP/skfolio结果或直接用新均值替换正式观点。原预测门槛由`gate_v57_forecasts.py`复核，仍要求多种子、相对F0增量、成熟历史和分块bootstrap，保守沿用原残差历史300日要求。通过某组件也不代表三产品或执行层晋升。

## 四、收益账本不是一个布尔开关

已核实本地有4,385条去重合同票息记录，曾持有的个券951只，但仅一条已核验终止兑付；V54仍有10,846条桶×券×日缺估值记录。合同利率不证明实际支付，公告计划也不证明到账。缺失事件不能按“没有票息”解释。

逐券清单`cashflow_evidence_requests.csv`列出待补记录日、除息日、实际支付日、每张本息、注销/兑付、原始公告和可见时间证据。REIT分派到账、曲线代理的可交易映射及券别成本仍需认证。本轮不伪造公告或把合成曲线当实盘产品。原始库只读。

`require_execution_certificate`核验数据哈希、38资产集合、完整现金流/公司行为/执行价格/成本/独立复核标记及实际证据文件SHA256。不能仅写一个true绕过。没有证据时正式PPO明确阻断；需要逐项完成真实对账才能解除，不因预测改善自动变true。

## 五、PPO的职责与自适应

保留项目已有PPO实现，不手写替代算法。它每天可选择不动、执行目标差额25%、50%、100%，因此调仓间隔由连续hold动作自然形成，不受5/20/60预测期限强制约束。输入应是当期均值观点、预测区间宽度、下行风险、当前持仓、目标偏离、距上次交易天数及预估成本。已有v45执行环境已包含这些类别的部分观测。

新增`execution_observation`与证据门负责接口测试；绝不把未来实现收益或训练用回撤标签放进观测。真实奖励应来自T+1执行账本的成本后收益，并与同目标机械执行对照；未认证时不训练正式PPO。接口通过不等于PPO已经训练，不以合成测试收益冒充回测。

## 六、运行与产物

GPU环境：`.venv-gpu-v55/Scripts/python.exe`。

```powershell
& '.venv-gpu-v55/Scripts/python.exe' -u -X utf8 scripts/run_v57_full_pipeline.py
```

脚本顺序执行六项单元测试、诊断和证据清单、15个训练任务、原门控、执行阻断回执。训练期间每5轮写loss.csv、输出进度；完成任务保存模型、预测和forecast_arrays，安全续跑只跳过身份哈希一致的已完成任务。未完成任务目前从该种子重新开始，不声称恢复优化器随机状态。不得同时启动重复进程。

所有新产物在`output/reports/multitask_v57`、`output/models/multitask_v57`、`data_processed/multitask_v57`。开始后不修改已登记的模块、训练入口、配置或本设计文档。即使loss下降也不承诺高夏普，不因失败无限网格搜索。

方法参考：[iTransformer原论文](https://arxiv.org/abs/2310.06625)、[PPO原论文](https://arxiv.org/abs/1707.06347)。它们不证明本项目有交易优势。研究判断参考本地经验库K1291、K1343、K1281的适用条件与执行成本核查，不把其历史案例作为训练标签或当前交易结论。
