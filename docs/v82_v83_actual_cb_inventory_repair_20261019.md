# 转债事件接入真实篮子库存：本次修复与剩余问题

## 先说结论

本次完成了2018-01-02至2026-10-14、1,012只转债、12个自建转债篮子的连续库存重放。使用现有V51的逐日可买信号，下一交易日收盘成交，按买卖实际金额分别计5bp成本。没有训练模型，没有修改38资产名单、九宫格、旧模型或旧版数据。

修复确实落到了实际篮子账中，但没有得到可以宣布完整回测通过的结论：

- 旧账11,563个缺估值持仓日，合并修复后10,846个，净减少717个。
- 广汽兑付消除了2,282个原缺口。资金重新可用后改变后续买入，新增1,565个缺口，其中蓝盾转债1,550个、思创转债13个、皖天然气转债2个。
- 这反映了资金路径变化，不是修复把后续行情补坏了，也不能仅统计消失的缺口来夸大改善。
- 仍未认证完整付息和全部退出事件，不生成正式总回报标签、夏普或PPO奖励。

## 一、为什么此前补过公告，真正的缺口仍然在

V70已经核验双环、欧派、淮矿、永创、骆驼、金力、钧达7只券的赎回事实。但此前案例使用的并非这12个篮子的实际登记库存。

本次把7个事件接入V51实际交易路径后，7只券在登记日的持仓全部为零：此前已按策略卖出，因此不能记兑付款，原11,563个缺口也不会减少。这些证据仍有存档价值，但不应算作当前篮子现金流缺口已修复。

随后发现V54已经保存广汽转债的到期方案和兑付结果，重新核验了缓存PDF哈希、113009证券代码、登记日、每张106元及兑付总额。此次合并接入，没有重新下载或更改旧原始文件。

## 二、修复的时点问题

旧V52校验要求付款确认日不晚于付款日，而发行人兑付结果常在付款后公布。同时，旧付款函数没有独立按证据可见日过滤。

新适配器 `src/v82_causal_cb_events.py` 将两个概念拆开：

1. 方案已可见后，登记日收盘按本账真实数量登记权益。
2. 注销日取消债券库存，并把登记权益乘方案金额记为应收款。
3. 计划付款日不能单独触发现金到账。
4. 发行人结果公告可见后，且不早于经济付款日，才允许把应收款转成现金。
5. 公告按下一国内交易日保守生效，不因后来取得结果而回填之前的可用现金。
6. 应收款不能借给买单使用，未付现金流不计作购买力；错误步骤整日回滚。

广汽的具体时点：方案公告2022-01-18，保守可见2022-01-19，登记2022-01-21，注销与经济付款2022-01-24，结果公告2022-01-24，重建账中现金确认2022-01-25。

这是依据发行人结果重建的税前历史会计路径，不能声称拥有用户个人账户银行流水。方案金额包含到期兑付约定，后续补付息时必须识别最终一期是否已包含，防止重复。

## 四、验证了什么

- 无事件控制账逐日复现V52原净值诊断与缺估值数量，25,524个日期×篮子坐标一一对应。
- 成交数量累计减去登记注销数量，与期末库存一致。
- 登记应收款等于仅支付一次的确认金额，未借款，未把现金确认倒填到公告前。
- 8个真实事件确认前的截断检查：移除当时尚不可见的方案及未来付款确认，当前步骤的库存、现金、应收款、成交与暂定NAV不变。这是事件层截断检查，不等于全项目所有输入都已完成因果认证。
- V81/V82共15项回归测试通过，包括提前确认不能提前付款、失败整日回滚、付息不注销证券、同日信号拒绝、未来确认删除及重复付款防护。
- 原始文件哈希在运行前后核验；没有拉行情、调参、选择收益更高路径或恢复任何晋升门槛。

未认证总回报NAV保持缺失。暂定估值不得冒充可交易总回报或拿去算新夏普。
